# KV-T G1 单 Region v2 KV 读写 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 落地 issue #141——`coord.kv.v2` 的 Put/Delete/Range 在单 Region 上端到端工作：显式 `commit_ts`/`read_ts`、header `read_ts`、`CommitRejected`/`SAFE_TS_LAG`/`OUT_OF_RANGE` 映射、`coord-client` 最小 v2 调用与指标。

**Architecture:** v2 handler 复用 v1 的 Region 路由/线性一致读屏障/raft 写超时，但写命令改走 `Command::PutV2`/`DeleteV2`/`DeleteRangeV2`（revision=`commit_ts`），读路径按 `read_ts` 选实时视图或 changelog 历史视图。G1 的 `safe_ts` 就是单 Region 的 `current_revision`（全部已 apply）；#142 只替换水位来源，不改变“`read_ts=0` 取安全水位、超过时等待/`SAFE_TS_LAG`”的语义。历史读的 `create_revision`/`mod_revision`/`version` 由 changelog 重放得出，`lease_id` 在 G1 恒为 0（#145 前 v2 写入拒绝非零 lease）。

**Tech Stack:** Rust、tonic/prost、openraft + redb、coord-proto v2、coord-client。

**Spec:** `docs/adr/0015-kv-t.md` D3/D11/D12.1/D12.3/D12.5 + issue #141；字段语义以 `apis/contracts/proto/coord/kv/v2/kv.proto` 头注为准。

## Global Constraints

- `[kv_t].enabled=false`（默认）时 v1 行为、服务注册、磁盘布局不变（ADR-0001）；v2 RPC 仍返回 `FAILED_PRECONDITION`。
- `commit_ts`/`read_ts` 是全局 TSO 值；服务端**不**替调用方分配 `commit_ts`（D12.1：直写是内部/高级路径）。
- 用户级拒绝（`CommitRejected` 等）不得让 raft apply 返回 `Err`（D11.5）；错误必须带结构化 trailer，调用方按码分支。

## Rulings

- **issue 的“写分配 commit_ts”按 D12.1 解释**：`coord.kv.v2` 写接口要求调用方自带 `commit_ts`；普通业务写入走 `coord.txn.v2`（G3）。本项让最小客户端先从 `coord.tso.v2.GetTs` 取一个值再直写，既验证 TSO 链路，也不在服务端偷偷分配（否则同一事务多 key 的原子 commit_ts 无从保证）。
- **G1 的 SafeTs**：单 Region 下 `current_revision` 即“已 apply 的全局水位”，`read_ts=0` 取它；`#142` 落地后改为全局 SafeTs 来源，等待/拒绝语义不变。
- **lease 门禁**：`lease_id != 0` 返回 `FAILED_PRECONDITION`（点名 #145）。原因：v2 Lease 尚未交付，v1 的按 log-index `DeleteKeysByLease` 会在 `CommitTs` 模式删除数据却不推进 revision，破坏 D11.2/7；宁可显式拒绝，不制造混合语义。
- **`request_id` 幂等**：命中时回放首次完整响应（命名空间隔离 v1/v2）；无 `request_id` 时同一 `commit_ts` 仍由存储层保证“不重复写/不重复推进 revision”，但首次 `deleted` 计数不保证跨境重放一致——完整幂等重试面归 #151。
- **历史 `lease_id`**：G1 所有 v2 写入 lease=0，因此历史读返回 0 是当前事实；#145 打开 lease 写路径时必须让 changelog 携带 lease 或提供历史 lease 来源。
- **`coord-routing-epoch`**：G1 单 Region 不校验；#161 在所有数据面入口统一接入 `EPOCH_STALE`。

## Review Focus

1. **不静默写**：`commit_ts <= current_revision` 且未命中已有 revision → `FAILED_PRECONDITION` + `COMMIT_REJECTED`，数据不落盘。
2. **读己之写**：`Put(commit_ts=100)` 后 `Range(read_ts=0)` 必须返回该值且 `header.read_ts >= 100`；`Range(read_ts=100)` 的快照视图一致。
3. **不越界等待**：`read_ts > current_revision` 只等 `read_ts_wait_ms`，超时 `UNAVAILABLE` + `SAFE_TS_LAG`（可重试），不得无限阻塞。
4. **历史读不撒谎**：`read_ts` 早于 compact 水位 → `OUT_OF_RANGE`；历史 `mod_revision` 是最后一次 <= read_ts 的写入，不是 `read_ts` 本身。
5. **v1 零影响**：默认关闭/`RevisionMode::LogIndex` 下 v1 Put/Range/Delete 与改动前一致。
6. **规模闸**：显式 `limit` 或 `count_only` 命中超过 `[kv_t].max_range` → `INVALID_ARGUMENT` + `READ_SET_TOO_LARGE`，不得无界扫描。

- 解析 `limit`（负数 `INVALID_ARGUMENT`；0 → `max_range`；> `max_range` → `READ_SET_TOO_LARGE`）。
- `read_ts=0` → `mvcc.current_revision()`；`read_ts>current` → 先 `ensure_linearizable_on`，再按 `read_ts_wait_ms` 每 10ms 轮询 `current_revision`，超时 `UNAVAILABLE + SAFE_TS_LAG`（递增指标）。
