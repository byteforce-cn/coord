# KV-T G3（#149）OCC 谓词校验与冲突重试 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 Commit Sequencer 在 `(start_ts, commit_ts]` 内校验 range 读谓词（防幻读），
并把读集/区间扫描上限变成明确、fail-closed 的用户级结果；冲突不写决策、换新
`start_ts` 重试可成功。

**Architecture:** 保留 #146 的 `SequencerOp::ValidateAndCommit`（旧日志兼容）不动，**末尾追加**
`ValidateAndCommitWithRanges`：候选事务带 `read_ranges`，并把 leader 配置的
`max_read_set` / `max_range` 一并写进命令。apply 在同一个 redb 写事务里先校验 point
索引（既有路径），再对每个 `[start, end)` 走 #147 的有序区间索引；区间扫描与同批
前序事务的写入在同一事务里可见。扫描超预算返回 `Invalid`（不是 `Conflict`、更不是
`Clear`），冲突/上限都不写 `CommitDecision`。

**Tech Stack:** Rust、openraft/redb、serde/postcard（无新增依赖/RPC/配置项）。

**Spec:** `docs/adr/0015-kv-t.md` D4/D9/D11/D12.2 + issue #149；前置 #144/#147/#148；
消费方 #151；总表 #127。

## Global Constraints

- `[kv_t].enabled=false`（默认）时不提案、不校验任何 v2 事务，v1 行为字节级不变
  （ADR-0001）。
- 用户级冲突/上限**不得**让 raft apply 返回 `Err`（D11.5）；只体现在
  `SequencerOutcome` 里。
- 冲突与 `Invalid` 都不写 `CommitDecision`；已决策事务仍按 #148 原子 apply，不受本项影响。
- `CommitDecision` 格式与 #148 的跨区应用不变；本项只改 sequencer 校验输入/结果。
- 校验上限必须确定性：值随命令进 raft 日志，apply 只读日志里的值，不读本地配置。
- 区间语义与 `range_in`/`ReadRange` 一致：`[start, end)`；`end` 为空 = 无上界；
  `start >= end`（end 非空）= 空谓词，永远 `Clear`。
- 删除也是写：range 谓词必须能被 Delete 命中（#147 索引已保证）。
- 不新增 `TODO`/`FIXME`；临时文件只放 `/tmp`；注释只写当前「为什么」。

## Rulings

- **末尾追加新命令变体，不改 `SequencerTxn` 字段**：raft 日志/快照用 postcard，
  非自描述；给结构体加字段会让旧日志解码失败。`SequencerOp` 既有约定是变体末尾追加，
  因此新增 `ValidateAndCommitWithRanges`，旧 `ValidateAndCommit` 继续按原语义 apply。
- **上限随命令传递，不读本地配置**：`max_read_set` / `max_range` 由 leader 从
  `[kv_t]` 写入命令；各节点即使配置漂移，apply 结果仍一致。`0` 沿用既有查询约定
  （不限制），正常启动路径由配置校验拒绝 0。
- **超预算返回 `Invalid` 而非 `Conflict`**：`Exceeded` 表示「无法证明无冲突」，不是
  「已证明冲突」。它不是瞬态竞争，换新 `start_ts` 也不会消失，必须让调用方收窄谓词
  或拆分事务；#151 映射到 `INVALID_ARGUMENT` + `READ_SET_TOO_LARGE`。`#147` 的
  `Exceeded` 不得退化成 `Clear`。
- **读集条目上限在冲突校验前判定**：超限是输入非法；先报上限，不让一个超大读集拖垮
  逐条校验。point + range 谓词各算一条（与 #144 `ReadSet::len` 一致；空谓词也计入）。
- **校验顺序 = point 先、range 后（range 按输入顺序）**：保持 #146 既有 point 冲突
  结果不变；range 命中取索引里的最大 `commit_ts`（同 ts 取字典序最小 key，#147 已固定），
  因此同一日志在所有节点重放出同一 `conflict_key/conflict_ts`。
- **同批可见性必须走写事务**：校验函数接收当前 `WriteTx` 并在其中扫描区间索引；
  不能调用 `self.backend.read`，否则同批前序事务刚写的索引不可见，会产生假阴性。
- **`Commit` RPC、TTL/abort、leader 故障切换不在本项**：分别归 #151、#150、#152；
  本项只提供可独立测试的内部 sequencer 面，并用「换新 `start_ts` 重试成功」证明冲突
  可恢复。#144 的 `TxnSessions` 仍不暴露读集（#151 消费时再加 `take_read_set`）。

## Review Focus

1. **同批假阴性**：同一 raft 批内，前一条事务写入的 key 必须让后一条的 range 谓词冲突。
2. **幻读**：range 读之后、commit 之前插入的 key 必须让 range 谓词冲突，且不写决策。
3. **空/无界区间**：`[c,c)`、`[e,b)` 永远 `Clear`；`[m,"")` 要能扫到 `m` 之后的写，
   不能扫进 `/_sys/seq/` 的其他前缀。
4. **预算 fail-closed**：扫描项数 > `max_range` ⇒ `Invalid(RangeScanExceeded)`，
   不得当 `Clear`；读集条目 > `max_read_set` ⇒ `Invalid(ReadSetTooLarge)`。
5. **旧日志兼容**：`SequencerOp::ValidateAndCommit` 的旧记录仍按原行为 apply；
   新变体在 postcard 里是追加索引，不改变旧变体索引。
6. **关闭态/回归**：`kv_t=false` 时不构造 sequencer；#146/#147/#148 的测试与 v1 测试不变。

## 验收矩阵

| 用例 | 断言 |
|:--|:--|
| write skew | 后提交的事务在读集被写命中时 `Conflict`，不写决策 |
| range 幻读 | 读后插入的 key 让 range 谓词 `Conflict`；新 `start_ts` 重试成功 |
| 同批可见 | 同批前序事务的写入让后序 range 谓词冲突（不读独立快照） |
| 空/无界 | 空谓词永远 `Clear`；无上界区间命中 `start` 之后的写 |
| 扫描预算 | `Exceeded` ⇒ `Invalid(RangeScanExceeded)`；`max_range=0` 不限 |
| 读集上限 | 条目 > `max_read_set` ⇒ `Invalid(ReadSetTooLarge)` |
| 旧日志 | 旧 `ValidateAndCommit` 行为不变；新变体不影响旧变体索引 |
| 关闭态 | `kv_t=false` 时不构造 sequencer，v1/既有 G1–G3 测试不变 |
