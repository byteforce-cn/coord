# MQ v2 M6-1（Java 半边）— Java SDK、consumer helper 与真实集群 IT 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** `cn.byteforce.coord.sdk.mq.v2` 提供与 `coord.mq.v2` 契约对齐的 Java 客户端
（19 RPC 中 18 个；`Subscribe` 按 best-effort 边界不实现）与一个消费组 helper，能在真实
v2 集群上跑通「建 topic → 发布 → 组消费 → Ack → DLQ → 删除」全链路，并在
`java-example` 给出可运行示例。

**Architecture:** SDK 走既有 Agent 通道（`AgentRpcClient`）：v2 的 MQ 服务由 Agent
`MqV2Proxy` 转发（Rust 半边已在 #361 补齐 18/19）。Java 侧只做 wire 映射、错误码透出与
consumer helper（Join → Poll → 处理 → Ack → Heartbeat → 再平衡重连），不实现 Leader 重定向
（由 Agent 侧 `MqV2Client` 缓存 + 重试承担）。

**Tech Stack:** Java 21（records / sealed 边界不用）、gRPC blocking stub（
`cn.byteforce.coord.contracts.mq.v2`，由 `coord-proto/src/proto` 生成）、JUnit 5 + AssertJ。

**Spec:** `docs/adr/0016-mq-v2.md` D9/D12；`docs/production/consumer-contract.md` §5.6/§5.7；
`apis/contracts/proto/coord/mq/v2/mq.proto`（19 RPC 的权威形状）；
`docs/production/ops/mq-v2-gate.md` M6-1 行。

## Global Constraints

- **契约面逐字对齐**：字段名/语义以 `mq.proto` 头注为准；`topic_epoch`、`generation`、
  `member_id` 必须显式传递（`0` = 不校验只用于读取面，SDK 不得省略写面代际）。
- **错误按码分支**：`CoordException` 已带稳定码（`TOPIC_NOT_FOUND`/`TOPIC_EPOCH_STALE`/
  `OFFSET_OUT_OF_RANGE`/`GROUP_EPOCH_STALE`/`REBALANCE_IN_PROGRESS`/`NOT_LEFT` 等）；
  禁止解析异常文案。
- **至少一次**：`MqV2Consumer` 只在处理成功后 `ack`；重复投递是正常形态，helper 不吞异常、
  不自动跳过位点。
- **不实现 Subscribe**：契约明确 best-effort（背压丢弃、不推进位点）；SDK 不提供该方法，
  Javadoc 指向 `poll`+`ack`。
- 默认超时与重试沿用 `CoordConfig.requestTimeout` 与 `RetryTemplate`；新增 RPC 一律
  `callWithRetry(..., "mqV2.<rpc>")` 以便观测。
- 不新增 `TODO`/`FIXME`；Javadoc 写明边界（不静默承诺）。

## Review Focus

- **`topic_epoch` 传递**：删除重建后旧 epoch 必须失败（`TOPIC_EPOCH_STALE` /
  `TOPIC_NOT_FOUND`），helper 不得把 0 当"自动"。
- **再平衡**：`Heartbeat.rebalance_required` 或 `GROUP_EPOCH_STALE` ⇒ 立即重新 Join 并
  从已提交位点续读；旧代际的 `Ack` 必须失败（不得被吞）。
- **位点越界**：`OFFSET_OUT_OF_RANGE` 交给调用方的 reset 策略（`Earliest`/`Latest`/`Fail`），
  默认 `Fail`（不静默丢历史）。
- **二进制消息**：`key`/`payload` 是 `byte[]`，不得假设 UTF-8；`toString` 不打印 payload。
- **DLQ**：`PollDlq` 返回的 `dlqReason`/`dlqDetail` 保留原始 offset；`MoveToDlq` 幂等
  （`alreadyMoved=true` 也算成功）。
- **示例可跑**：`java-example` 的 v2 MQ 示例在 `ci-java-it-cluster.sh start v2` 集群上
  可执行，失败时给出启动集群的提示（与 `KvTV2ClusterIntegrationTest` 同口径）。

### Task 3: `MqV2Consumer`（Join → Poll → 处理 → Ack → Heartbeat → 再平衡）

**Files:**
- Create: `.../sdk/mq/v2/MqV2Consumer.java`
- Create: `.../sdk/mq/v2/MqV2ConsumerOptions.java`（builder：group / topics / memberId /
  sessionTimeoutMs / resetPolicy / maxMessages / maxBytes / waitMs / heartbeat 间隔）
- Create: `.../sdk/mq/v2/MqV2ResetPolicy.java`（`EARLIEST` / `LATEST` / `FAIL`）

**Interfaces:**
```java
public final class MqV2Consumer implements AutoCloseable {
  public static MqV2Consumer join(MqV2Client client, MqV2ConsumerOptions options);
  public String memberId(); public long generation();
  public List<MqV2TopicPartition> assignments();
  public List<MqV2Message> poll();
  public long ack(MqV2Message message);
  public void close();   // LeaveGroup（幂等）
}
```
语义决定：
1. 内部单线程心跳（`ScheduledExecutorService`，间隔 = `heartbeatIntervalMs`，0 ⇒ 10s），
   收到 `rebalanceRequired` / `GROUP_EPOCH_STALE` 置 dirty；下一次 `poll`/`ack` 前重新 Join。
2. 每分区维护 `nextOffset`（Join 的 `committedOffset` 或本地推进）；`OFFSET_OUT_OF_RANGE`
   按 `resetPolicy` 处理（默认 `FAIL`，抛 `CoordException`）。
3. `close()` 停心跳 + `LeaveGroup`（异常只记 WARN，不抛）。
4. `ack` 在代际过期时重新 Join 后重试一次（与 Rust helper 一致）。
