**Goal:** 整节点离线备份/恢复后 MQ 数据（topic/epoch/消息/位点/offset 续写）完好；关闭 `[mq_v2]` 不破坏 v2 KV，重新开启后 MQ 数据仍在。

**Architecture:** 复用 `coord/tests/common/v2_cluster.rs` 的真实 3 进程集群与 `coord backup save/restore` CLI（停机后整目录原样复制）。`coord/tests/mq_v2_m6_backup_test.rs` 做 4 个阶段：写入 → 全集群停机/逐节点备份恢复/重启 → 关闭 MQ 重启（fail-closed + KV 可读）→ 重新开启（MQ 可续读/续写）。

**Tech Stack:** Rust + tonic + 真实 `coord server` 进程 + `coord backup` CLI。

**Spec:** `docs/superpowers/specs/2026-10-29-mq-v2-design.md` §6 M6-5；`docs/production/ops/runbook.md` §3.3；gate §5（回退口径）。

## Global Constraints

- 备份是**停机后**整目录复制（不是状态机快照）：必须 `kill -9` 并确认进程退出后再 `backup save`。
- 恢复用同 `node_id`、`bootstrap=false`；不得改端口/目录布局。
- 关闭 `[mq_v2]` 只停 MQ 服务，不改 v2 KV 数据；`enabled=false` 时 MQ RPC 必须 `FAILED_PRECONDITION`。
- 不新增生产代码开关；测试只改夹具的 `toml_extra`。
- 临时文件只放 `/tmp`（`tempfile` 默认）；门禁同 AGENTS.md。

## Review Focus

- **offset 续写**：恢复后新消息 offset 必须紧接已提交的最大 offset，不能回退或复用。
- **committed 位点**：组位点随 Region 状态恢复；恢复后 `GetCommittedOffsets` 仍为备份前值。
- **关闭不误伤**：`enabled=false` 时 v2 KV 按备份前 `commit_ts` 可读；重新开启后 MQ 数据可读。
- **fail-closed**：禁用时 MQ RPC 是 `FAILED_PRECONDITION`，不是 `UNIMPLEMENTED`/空成功。
- **边界**：二进制升级/回退未演练（无旧版本二进制）；回退口径以 gate §5 为准。
