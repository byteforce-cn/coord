# MQ v2 M6-2 (Ops) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** MQ v2 的故障面有 Prometheus 告警、可执行的 runbook 处置步骤和 dashboard 出口：发布非 Leader/拒绝/延迟、位点越界、Ack 被拒绝、组再平衡/会话过期、死信增长、Subscribe 背压丢弃。

**Architecture:** 只消费 `coord-server/src/metrics.rs` 已导出的 `coord_mq_v2_*` 指标，不新增代码/指标。告警集中到 `monitoring/prometheus-rules.yml` 的新 group `coord-mq-v2`；每条告警的 `runbook_url` 指向 `docs/production/ops/runbook.md` §6 的同名处置小节，由 `scripts/check-gate-drills.sh` 机器校验（锚点存在 + 无孤儿小节）。Grafana 加一个 MQ v2 行（Publish/Poll、Groups/DLQ/Retention 两面板），`docs/production/ops/observability.md` 登记「指标 → 告警 → runbook」闭环。

**Tech Stack:** Prometheus / Grafana JSON / Markdown。

**Spec:** `docs/superpowers/specs/2026-10-29-mq-v2-design.md` §6 M6-2；`docs/production/ops/mq-v2-gate.md` M6-2 行；ADR-0016 D13（未达标即停止，不静默降级）。

## Global Constraints

- **不新增代码/指标/依赖**：v2 指标已由 M2-5/M3-6/M4 接线；本计划只做告警/runbook/dashboard/文档。
- 每条告警必须有 `runbook_url`，锚点必须真实存在；§6「告警处置」里不得有孤儿小节（由 `check-gate-drills.sh` 断言）。
- 告警阈值只做**症状可发现**，不是 SLO 校准；文档不得声称已校准。
- **不把 v1 MQ 指标混进 v2 告警**：v2 告警只用 `coord_mq_v2_*`；v1 的 `coord_agent_mq_consumer_lag` 与 `CoordMqConsumerLag` 保持原样。
- 告警名以 `CoordMqV2` 开头，避免与 v1 `CoordMqConsumerLag` 冲突。
- 注释/文档描述当前态；不写日期/变更史；不新增 `TODO`/`FIXME`。
- 临时文件只放 `/tmp/coord-*`；门禁同 AGENTS.md。

## Review Focus

- **告警在服务关闭时会不会误报**：`[mq_v2].enabled=false` 时指标仍在导出（值为 0）；所有 `increase(...) > 0` 不得触发，比率类告警用 `clamp_min` 防 0/0。
- **`OFFSET_OUT_OF_RANGE` 不是服务端故障**：告警只能提示"保留窗口已越过消费者"，处置是客户端 reset 策略，禁止建议调大保留期掩盖。
- **Ack 被拒绝不是"重试就好"**：`GROUP_EPOCH_STALE`/`NOT_GROUP_MEMBER` 的处置是重新 Join；禁止手工改位点或跳过代际校验。
- **DLQ 入队是症状不是原因**：告警给出 `reason` 的排查入口（`PollDlq`），不承诺"自动重放"。
- **Subscribe 丢消息是契约内行为**：处置是改 `Poll`+`Ack`，不是调大 buffer（契约明确背压丢弃）。
- **lag/配额/保留没有连续 gauge**：dashboard/runbook 用 `DescribeGroup`/`DescribeTopic` 的按需查询；不得声称有实时 lag 指标。
