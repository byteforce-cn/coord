# KV-T G1 TSO 状态机 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 落地 issue #136——在 region 0 system raft 上提供持久化、单调、绝不复用的全局 TSO 批次，并把 `coord.tso.v2` 的 `Allocate`/`GetTs` 接到该状态机。

**Architecture:** TSO 高水位是 region 0 状态机的一行系统记录（`TABLE_KV` 的 `/_sys/tso/*`，随 `/_sys/*` 域进入快照），批次通过 `Command::Tso(TsoOp::Allocate{batch_size})` 入 raft 日志，apply 在同一写事务里推进高水位、写 changelog 幂等标记与 `META_LAST_APPLIED`。`TsoAllocator` 只在 region 0 leader 本地 `client_write`；follower 返回 `NOT_LEADER`（转发留给后续工作项）。`GetTs` 先按 `Allocate(1)` 实现；#137 再接入本地批次缓存。

**Tech Stack:** Rust、openraft、tonic/prost、redb、postcard 信封 V2。

**Spec:** `docs/adr/0015-kv-t.md` D2/D11.3/D12.1/D12.4 + issue #136（验收项以 issue 为准）。

## Global Constraints

- `[kv_t].enabled=false`（默认）时 v1 行为、磁盘布局、服务注册字节级不变（ADR-0001）。
- TSO 只增不减、允许空洞、**绝不复用**；重启/换 leader 后新批 `start_ts` 必须大于已发放上界。
- 仅 region 0 leader 分配；follower 返回 `UNAVAILABLE` + 结构化码 `NOT_LEADER`（不解析文案）。
- 用户级失败不得让 Raft apply 返回 `Err`；apply 期不读墙钟/随机数（确定性）。
- 注释只写当前「为什么」；不新增 TODO/FIXME；临时文件只在 `/tmp`；文档引用 0 悬空。
- 提交前本地跑：`cargo fmt --all -- --check`、`cargo clippy --workspace --lib --bins -- -D warnings`、`bash scripts/check-panics.sh`、`cargo test`、`cargo audit`、`cargo deny check`、`bash scripts/check-doc-refs.sh`。

## Review Focus

1. **崩溃/换 leader 后复用**：分配返回后进程在客户端使用前崩溃 → 新 leader 的下一批必须高于旧 `end_ts`（持久化高水位，不是内存计数）。
2. **follower 静默分配**：非 leader 调用必须 `NOT_LEADER`，不得本地写盘造成双高水位。
3. **批大小边界**：`batch_size=0` 视为 1；超过 `[kv_t].tso_batch_size`/65536 返回 `INVALID_ARGUMENT`，不得静默截断。
4. **快照回退**：装快照/重启后高水位不得倒退（记录位于随 `/_sys/*` 导出的域）。
5. **重放幂等**：同一 revision 重复 apply 返回同一批次、不推进高水位。
