# MQ v2 M6-4 (混沌/Jepsen) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** MQ v2 在分片/组 Leader 进程死亡、网络分区与配额打满后仍满足 offset 唯一/连续、committed 单调、整批原子；故障矩阵进 CI chaos job。

**Architecture:** 复用 `coord/tests/common/v2_cluster.rs` 的真实 3 进程 v2 集群（debug 构建的 raft-RPC 分区钩子）；`coord/tests/mq_v2_m6_chaos_test.rs` 用 SDK（`coord_client::Client::mq_v2()`）做带重试的数据面操作，故障后校验不变量。CI 在既有 chaos job 里构建并执行该 test target。

**Tech Stack:** Rust + tonic + 真实 `coord server` 进程（kill -9 / SIGSTOP / 分区文件钩子）。

**Spec:** `docs/superpowers/specs/2026-10-29-mq-v2-design.md` §6 M6-4；ADR-0016 D13。

## Global Constraints

- 故障注入只经夹具：`V2Cluster::{kill9, start, partition, heal}`；不改生产代码做测试开关。
- `partitionable: true` 依赖 **debug 构建**的 `COORD_TEST_RAFT_PARTITION_FILE`；release 下该选项无效。
- 每个场景都断言不变量，而不是"进程还活着"：offset 集合、committed 单调、整批原子。
- 样本门槛：分片 Leader 故障场景至少 100 次发布入样本（Jepsen 风格的最小操作量）。
- 不新增指标/配置；临时文件只放 `/tmp/coord-*`。

## Review Focus

- **kill -9 后客户端缓存**：只有 `NOT_LEADER` hint 才刷新的缓存，会让分区永久钉在死地址；无 hint 的 `UNAVAILABLE` 也必须驱逐。
- **组 Leader 故障**：Ack 可能先返回 `GROUP_EPOCH_STALE`/`UNAVAILABLE`；重试必须保持 committed 单调，不能把已 Ack 的位点回退。
- **配额是整批原子**：跨配额批量发布不得分配任何 offset；拒绝后下一条 offset 紧接已提交。
- **分区不是 kill**：follower 被隔离时 2/3 多数派仍可写；heal 后 offset 必须连续。
- **快照安装**：MQ 段随 Region 快照恢复，本套件不重复注入 snapshot install（由 KV-T chaos 覆盖）；gate 里如实写边界。
