# MQ v2 M5-3/M5-4 — MQ 触发器与全链路实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 workflow 定义能声明 MQ 触发器：durable 引擎按定义加入消费组，`Poll` 到的消息以
`mq:<topic_id>:<partition>:<offset>` 为幂等键 `Start` 实例，**Start 持久化后才 `Ack`**；崩溃
重投不重复建实例，连续失败到 `max_attempts` 移 DLQ 并 `Ack`；再由全链路 e2e 证明
publish → trigger → workflow → outbox → 下一事件 的闭环。

**Architecture:** 触发声明是定义的一部分（顶层 `trigger` 块，随 `WorkflowDefinition` 持久化）；
Start 幂等由**确定性实例 id**（`sha256(definition_id, idempotency_key)`）承担 —— 同键重放直接返回
已存在实例，不新增存储 CAS、也不会把已完成的实例重置回 `Pending`。分发器是 Agent 侧新模块
`workflow_trigger.rs`：周期性对账已部署定义 → 每个声明了 trigger 的定义一个
`coord-client::MqConsumer`（`Join → Poll → 过滤 → Start → Ack`），只在
`data_plane="v2"` + `workflow_durable` + `mq` 三前置齐备时装配。

**Tech Stack:** Rust 2021、`coord.txn.v2`/`coord.kv.v2`、`coord.mq.v2`、`coord-client`
（`MqV2Client` / `MqConsumer`）、tonic 0.14、tokio。

**Spec:** `docs/adr/0016-mq-v2.md` D12（触发语义与不变量）；
`docs/superpowers/specs/2026-10-29-mq-v2-design.md` §6 M5-3/M5-4/M5-5；
`docs/production/ops/mq-v2-gate.md` §2e。

## Global Constraints

- **v1 字节级不变**：`data_plane="v1"` 的装配、`WorkflowStartRequest` 旧字段语义、v1 MQ 行为逐字
  不变；`trigger` 在 v1 durable 下**不装配**（`schedule.on` 仍走进程内事件），不静默替换语义。
- **Ack 纪律**：`Start` 返回成功（实例已落库）之前绝不 `Ack`；`MoveToDlq` 成功后才 `Ack`。
- **幂等键格式固定**：`mq:<topic_id>:<partition>:<offset>`（`topic_id` 取 `GetTopicLeader`，
  删除重建后 `topic_id` 变化 ⇒ 新消息是新键）。
- **topic 必须已存在**：触发器**不**自动 `CreateTopic`；`JoinGroup`/`Poll` 的 `TOPIC_NOT_FOUND`
  按可重试处理并记 WARN（不静默建 topic、不静默丢消息）。
- `max_attempts` 默认 **3**，合法区间 **1..=32**；到限后的 DLQ `reason` 固定为
  `workflow_trigger_max_attempts`（稳定锚点，日志/测试逐字断言）。
- 消费组名固定 `wf-trigger:<definition_id>`（≤255 字节，`mq_group::validate_join` 的上界）。
- 越界位点（保留期删段）按 `ResetPolicy::Earliest` 重置并 WARN，不静默停摆。
- 非测试代码不得 `unwrap/expect/panic/unimplemented/todo`；`scripts/check-panics.sh` 为 0。
- 新增/改动引用后跑 `bash scripts/check-doc-refs.sh`（悬空路径必须为 0）。
- 不新增 `TODO`/`FIXME`；提交前本机跑通 lint 四件套 + `cargo audit` + `cargo deny check`。

## Review Focus

- **过滤不命中**：`filter` 不匹配的消息对该组**照常 `Ack`**（组已消费），不能卡住分区后续消息。
- **重复投递**：崩溃/再平衡后同一 `(topic, partition, offset)` 重投，必须命中同一实例（同键），
  实例数不增；已 `COMPLETED` 的实例不得被重置回 `Pending`。
- **毒消息**：Start 连续失败到 `max_attempts` → `MoveToDlq`（幂等：`already_moved` 也算成功）→ `Ack`；
  不 `Ack` 会让分区永久卡死。
- **触发器不建 topic**：topic 不存在时触发器持续 WARN 重试，绝不 `CreateTopic`（与 durable
  事件 topic 的幂等引导是两条路径）。
- **定义变更/删除**：定义被重部署成无 trigger / 被删除后，旧消费者必须停下（不再 `Start`）。
- **多 Agent**：同一定义在 N 个 Agent 上是**同一个组**，一个分区只归一个成员；再平衡后从已提交
  位点续读，不重复启动已 `Ack` 的 offset。
- **v1 关闭路径**：`services.workflow_durable=false` 或 `data_plane="v1"` 时零副作用（不建组、
  不 Poll、只多一行"未装配"日志）。

**Files:**

**Interfaces:**
- Produces:
  - `pub struct TriggerDispatcher`，`pub fn new(inner: Arc<AgentInner>, engine: Arc<WorkflowEngineService>) -> Self`
  - `pub fn spawn(self: &Arc<Self>)`
  - `pub(crate) fn trigger_of(def: &WorkflowDefinition) -> Option<&TriggerConfig>`（空 = None）
  - `pub(crate) fn envelope(msg: &MqMessage) -> serde_json::Value`
    （`{topic, partition, offset, timestamp_ms, key(base64? 无 → hex), headers, payload}`）
  - `pub(crate) fn idempotency_key(topic_id: u64, partition: i32, offset: u64) -> String`
- Consumes: Task 1 `TriggerConfig`、Task 2 `start_instance_as_with_key`、Task 3 `move_to_dlq`、
  既有 `coord_client::MqConsumer`（`MqConsumerOptions`）、`WorkflowEngineService::list_definitions`

语义决定（实现前先读）：
1. **对账循环**（5s）：`engine.list_definitions("", usize::MAX, None)` → 取 `trigger.topic`
   非空且有 `def.id` 的定义；键 = `definition_id`；新出现的启动任务，消失的 `stop()`（`watch`
   信号 + `MqConsumer::close()`）。任务内部 `Join` 失败（topic 不存在/无 Leader）不退出，指数
   退避到 5s 上限后重试。
2. **单条处理顺序**：`poll()` → 逐条按 offset 顺序处理 → 过滤不命中**立刻 `Ack`** → 命中则
   `start`，成功 `Ack`、失败 `attempts += 1`（内存计数，键 = `(topic, partition, offset)`），
   到 `max_attempts` → `move_to_dlq`（`already_moved` 也算成功）→ `Ack` + `ERROR` 日志；
   未到限则按 `200ms * attempts` 退避后**重试同一条**（不再 `poll`）。
3. `topic_id` 由 `GetTopicLeader` 取一次并缓存；`TOPIC_EPOCH_STALE`/`TOPIC_NOT_FOUND` 时刷新
   一次再重试（与 `MqV2OutboxSink` 同一策略），刷新失败则丢弃消费者、交给对账循环重建。
4. 幂等键 `mq:<topic_id>:<partition>:<offset>`；`Start` 的 `initiator = None`（消息触发无终端用户）。
5. 装配条件：`data_plane == V2 && services.workflow_durable && services.mq`；否则只打一行
   `tracing::info!("workflow triggers not assembled (requires v2 + durable + mq)")`，零副作用。
