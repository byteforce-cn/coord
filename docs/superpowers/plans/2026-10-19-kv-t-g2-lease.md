# KV-T G2（#145）v2 Lease 与跨 Region 清理 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 交付 `coord.lease.v2` 的 Grant/Revoke/KeepAlive/TimeToLive，租约元数据落在 region 0
raft 状态机，KV v2 的 `lease_id` 绑定在 revoke/到期时按 key 所在 Region 清理；幂等、重启续跑；
`[kv_t].enabled=false` 时 v1 行为不变。

**Architecture:** 新命令 `Command::LeaseV2(LeaseV2Op)` 只经 region 0 system raft 提交，apply 写入
`/_leasev2/{id}`（与 v1 `/_lease/` 分离，v1 的 log-index 语义不受影响）。绑定关系不另建表：
key 的 `KvMetadata.lease_id` 是权威索引，`DeleteKeysByLeaseV2` 在各数据 Region 内按该索引
apply 期原子删除。Revoke 先经 TSO 取 `commit_ts`，再写 region 0 决策；删除按 Region 扇出，
失败/重启由 revoker 续跑。单 Region / legacy 路径直接清理 region 0。

**Tech Stack:** Rust、openraft/redb、tonic/prost、coord-proto v2。

**Spec:** `docs/adr/0015-kv-t.md` D3/D6/D11/D12.1 + issue #145；wire 语义以
`coord-proto/src/proto/coord/lease/v2/lease.proto` 头注为准（与 `apis/contracts/proto/...` 逐字节同步）。

## Global Constraints

- `[kv_t].enabled=false`（默认）时 v1 lease 行为完全不变；v2 服务门禁返回 `FAILED_PRECONDITION`。
- 租约元数据只在 region 0；数据 Region 只按 `KvMetadata.lease_id` 清理，不复制租约表。
- `commit_ts` 必须由 TSO 发放；lease 操作本身不推进 `META_CURRENT_REVISION`。
- 用户级冲突/重复 revoke 不得让 raft apply 返回 `Err`（D11.5）。
- 不新增 `TODO`/`FIXME`；临时文件只放 `/tmp`；注释只写当前「为什么」。
- 合入前跑 AGENTS.md 门禁（fmt / clippy / check-panics / audit / deny）+ `cargo test --workspace`。

## Rulings

- **租约表与 v1 分离**：v1 `LeaseOp` 的 revision=log-index 且会触发 v1 清理广播；v2 直接复用会让
  v2 删除落成 log-index revision。新增 `/_leasev2/` 前缀与独立命令，v1 路径零改动。
- **key 索引不双写**：`KvMetadata.lease_id` 已由 Put/Delete 维护，region 0 不维护 attached key
  列表；`TimeToLive(keys=true)` 从本节点各数据 Region 副本按上限收集（与快照读同一本地副本前提）。
- **清理的 `commit_ts`**：Revoke 在 region 0 决策时分配并记录 `revoked_commit_ts`。数据 Region
  若因更高 `commit_ts` 已 apply 而 `COMMIT_REJECTED`，revoker 重新分配时间戳并更新 region 0
  决策后重试；最终一致删除。跨 Region 同一 commit_ts 的严格原子可见性归 #148 的
  CommitDecision 应用路径，本项不提前承诺。
- **续期不取 TSO**：KeepAlive 只延长 deadline（与 contract 一致），不产生 commit_ts。
- **自动 id**：`lease_id = granted_ts = TSO`，天然全局唯一且单调；显式 id 冲突由状态机
  fail-closed 拒绝（不覆盖）。
- **TTL 上限**沿用 v1 的 86400 秒；超限 `INVALID_ARGUMENT`。
- **到期与续约的竞争**：expiry worker 把观测到的 deadline 随 `Revoke` 入日志，apply
  发现记录已被续期（deadline 更晚）则放弃本次到期清理——裁决在状态机内、确定性，
  不依赖 leader 墙钟。
- **清理可靠性**：revoker 启动扫描 + region 0 apply 广播 + 每 60s 重扫已 revoke
  记录（覆盖快照安装跳过日志 apply、没有广播的路径）；重复命令按 commit_ts 幂等。

## Review Focus

1. **v1 零变化**：`Command::Lease` / `/_lease/` / v1 revoker 路径未改；关闭 v2 时无后台任务。
2. **apply 不 wedge**：重复 revoke、未知 lease、commit_ts 冲突都返回结构化响应。
3. **重启续跑**：revoker 启动时扫描已 revoke 记录，逐 Region 重放同一命令（幂等）。
4. **绑定校验**：Put 绑定不存在/已 revoke/已过期 lease → `FAILED_PRECONDITION`，不写数据。
5. **单一事实源**：不改 ADR 语义；限制写进本计划与 PR 描述。

## 验收矩阵

| 用例 | 断言 |
|:--|:--|
| Grant 自动 id / 重复 request_id | 同 id、同 granted_ts，不重复分配 |
| Grant 显式 id 冲突 | `ALREADY_EXISTS`，原租约不被覆盖 |
| KeepAlive 流 | 剩余 TTL > 0 且 <= 配置 TTL；停止后到期 |
| TimeToLive(keys=true) | 返回两个 Region 的绑定 key |
| Revoke 多 Region | `commit_ts > 0`；两 key 均被删除；重复 revoke → 0 |
| 到期 | TTL 到点后 key 被清理；TTL 返回 <= 0 / KeepAlive NOT_FOUND |
| 重启续跑 | 只有已 revoke 记录、未清理的 key 被 revoker 启动扫描删除 |
| 绑定校验 | 未知/已 revoke lease 的 Put → `FAILED_PRECONDITION` |
| 门禁 | 未实现的 Lease 能力 → `FAILED_PRECONDITION`；关闭时同上 |
