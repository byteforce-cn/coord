## §0 你能拿到什么级别的承诺（先看这一段）

| 级 | 名称 | 门槛 | 对你意味着什么 |
|:--|:--|:--|:--|
| **L0** | 接口承诺 | P2 + P9 绿（**当前已达**） | wire 已冻结；**客户端只依赖 gRPC Status Code**，不解析内部错误串（`WHITEPAPER.md:304` §6.3） |
| **L1** | 受控试验接入 | L0 + 该能力 G1–G7 绿 + **你书面接受本手册 §3 的边界** | 可在**非关键路径**试点；风险共担；随时可回退 |
| **L2** | 生产可用 | **P-Gate 1–9 全绿**（**尚未达成**，见 §4） | 生产可用（本仓库当前**不得**声明） |
| **L3** | SLA / 规模承诺 | L2 + 容量规划 + 值守 + 常态化演练 | **不在本计划范围**；需要单独立文 |

> **不要说"生产可用"**：`WHITEPAPER.md:509`（§12.1）自己写着「GA 期限前请勿将 COMMITTED
> 契约当作生产可用面验收」。契约期限到点只说明"接口已冻结并挂载"，**不说明生产可用**。

## §1 接入面：只有 Java SDK（或你自带的 gRPC 客户端）

| 方式 | 状态 | 说明 |
|:--|:--|:--|
| **`coord-java-sdk`** | ✅ **唯一支持面** | 有单元测试 + 真实集群集成套件（CI 的 `java example integration` job 跑 `-Pit`） |
| 自带 gRPC 客户端 | ✅ 允许 | 契约是公开的：`apis/contracts/proto/**`；但你要自己实现重试/续传/watch 重连等语义 |
| Spring Boot starter | ❌ **不存在，且是产品决定** | 16 个文件在 `2b55809` 被删除且**不会恢复**。你要自己写 `@Bean` 并**自己管生命周期** |
| 其他语言 SDK | ❌ 无 | —— |

**Spring 接入配方（官方口径，`README.md` 的 Java 集成段同源）**：

```java
@Bean(destroyMethod = "close")   // ← 必须：不调用 close() 会泄漏（无 shutdown hook）
public CoordClient coordClient(CoordClientConfig cfg) {
    return CoordClient.create(cfg);
}
```

> **为什么 `destroyMethod` 是必须的**：SDK 的 `close()` 负责取消 MQ 订阅、完成挂起的
> workflow watch、停止心跳线程。不调用它，进程会**泄漏而不是优雅退出**
> （`remaining-known-gaps.md` §3 的残余项）。

**SDK 获取方式（U-06 裁定：不发布到制品仓库）**：
从仓库 tag 构建：`mvn -f coord-java-sdk/pom.xml -DskipTests install`。
**不发布**是有意的：当前没有消费方需要它，发布要额外承担版本流程与制品维护；
`java-example-it` 这条 CI job 仍然每次真实集群验证 SDK 可用性。

## §2 你必须知道的三件事（接入文档纪律）

1. **客户端只依赖 gRPC Status Code**：`WHITEPAPER.md:304` §6.3。内部错误串会变，
   不要 `parse` 它。
2. **结构化错误码在 trailer**：`x-coord-error-code`（值见 `CoordErrorCode::as_str`，
   Java 侧 `ErrorCode`）。**重试决策按它来**：`NOT_LEADER` / `UNAVAILABLE` /
   `RESOURCE_EXHAUSTED` / `DEADLINE_EXCEEDED` 可退避重试；`UNAUTHENTICATED` /
   `PERMISSION_DENIED` / `INVALID_ARGUMENT` **不可重试**。
3. **能力边界逐条知道**（下一节）。

## §3 边界清单（不承诺 —— 与 `docs/production/ops/boundaries.md` 同源）

| 面 | **不承诺** | 你要怎么做 |
|:--|:--|:--|
| **cache** | 不承诺跨节点原子；`max_size_bytes` **不强制**（只告警）；本地 TTL 内可能读到旧值（watch 会失效该前缀，但跨 agent 无保证） | 需要强一致的读走 KV，不要用 cache 当真相来源 |
| **MQ** | `Subscribe` 是 **best-effort**；`Poll` 的 `start_offset` 语义见 F-68 修复口径；DLQ 容量有界 | 关键消息要幂等消费 + 自己留水位 |
| **cb / rl（熔断/限流）** | **本地**状态，不跨节点共享 | 阈值按"单 agent 视角"设置；需要全局配额要自己在业务侧聚合 |
| **policy / RBAC** | Agent **本地**判定；**不持久化**（重启丢失，U-08 裁定） | 重启后重新下发策略；不要把它当审计唯一来源 |
| **transit（加密）** | KEK **不是外部 KMS**（由配置/启动材料派生；拿到配置即可推导 KEK —— `WHITEPAPER.md:520` 已披露） | 不要把 transit 当作"云 KMS 等价物"；高敏感密钥自己加密后再交给 transit |
| **lock / election** | 分区期间 **Leader 无自动故障转移**；lease 过期释放绑定 key 的契约见 F-27（已修，lab 复跑形态见 §4） | 锁的续约失败要按业务语义处理（不要假设"锁一定还在"） |
| **workflow / scheduler** | 契约期限是 **2027-03-31**；`drive` 死亡可观测（W5-4）但**不自动重启** | 关键流程要有自己的"卡住"检测 |
| **storage（对象存储）** | 快照恢复时**落后节点的本地 chunk 会被清空 rebuild** ⇒ 期间 Get 可能返回 `UNAVAILABLE`；**全集群配置须一致** | 读要能容忍短暂 `UNAVAILABLE`（重试） |
| **升级** | **不支持滚动升级**；**不声明 N-1 兼容**；**不声明跨版本快照恢复**（`docs/production/ops/upgrade.md` §1/§4） | 升级窗口要停业务或容忍失败 |
| **多 agent 拓扑** | 当前 lab 下 agent 间**不可达**（F-58）⇒ ISR 复制面与跨 agent 投递**无法验收** | 涉及跨 agent 复制语义的能力**不要**在试点里用 |
| **长跑** | 72h soak / ≥14 天连续运行 **尚未做**（§4） | 试点期自建观测（内存/重启次数） |

## §5 试点接入清单（W8-2 / W8-3）

### 5.1 准入（逐条打勾；缺一条就不该开始）

- [ ] 场景**非关键路径**，且能接受"随时切回原方案"
- [ ] 你已读完 §3 边界清单并**书面**确认（L1 的门槛就是这个）
- [ ] 只用 SDK 或自带 gRPC 客户端（不依赖 Spring starter）
- [ ] 客户端按 §2 的重试/错误码口径实现完毕
- [ ] 你自建观测：错误率、P99 时延、以及**该能力的可观测异常**（锁/租约/复制）
- [ ] 回退预案可执行：**1 小时内**切回原方案，且**数据可逆**（§5.3）

### 5.2 试点范围建议

单机房、单业务、单 agent、非关键路径、**不含**跨 agent 复制语义的能力。

### 5.3 回退与数据可逆性（必须写清楚）

| 项 | 要求 |
|:--|:--|
| 回退触发条件 | 错误率 > 自定阈值 / 出现数据不一致 / 影响其他业务 |
| 回退动作 | 切流量回原方案（双写期则停止写 coord） |
| **数据可逆** | 明确"coord 侧写入的数据在回退后怎么处理"：**丢弃** / **双写期只读** / **导出后清理**。没有这一条就不算有回退预案 |
| 时间承诺 | 1 小时内完成（不含数据迁移） |

### 5.4 接入方验收清单（把第四轮 §6.3 六条改写为当前 17 项现实）

| # | 验收项 | 判据 |
|:--|:--|:--|
| 1 | 契约包可用且 wire 冻结 | `bash apis/contracts/scripts/check-wire-sync.sh` exit 0 |
| 2 | 该能力有 e2e 证据（经 agent 与不经 agent **两条路径**） | 对应 `docs/production/evidence/<ts>-<cap>/` |
| 3 | 版本头正确（`coord.<domain>.v1`） | `check-wire-descriptor.sh` exit 0 |
| 4 | 文档与承诺一致（含**不承诺**清单） | 本手册 §3 + `boundaries.md` |
| 5 | **默认开关口径**已裁定且一致 | `coord-agent/src/service.rs` 的 `impl Default` ↔ 裁定表（U-03：默认关，显式启用即可用） |
| 6 | 故障注入下有 e2e 证据（G7） | 对应 `matrix-*` 档绿 + **负控制**存在 |
| 7 | 该能力进入 soak-mix 并在 72h 达标（G8） | ⏳ **未做**（P5） |
| 8 | 升级路径已告知（U-1…U-5） | 本手册 §3 + `upgrade.md` §4 |

## §6 沟通口径（别说错）

**可以说**：
- 「接口已冻结（L0），客户端可基于契约生成，不依赖服务端反射。」
- 「该能力可在**非关键路径**试点，我们与接入方共同承担风险，随时可回退。」
- 「安全面**未经独立第三方审计**——这是我们如实披露的边界。」（U-14）

**不可以说**：
- ❌「生产可用」（P-Gate 未全绿）
- ❌ 任何 SLA 数字（L3 未立文；`slo.md` 自己的红线写着"不得高于 §5.4-③ 的 quiet 可用率 0.95"）
- ❌ 把 COMMITTED 契约当"已验证的生产面"（`WHITEPAPER.md:509`）
- ❌ 「经第三方审计 / 已通过独立审计」一类表述（U-14：不采买外审，统一说"未经独立第三方审计"）
